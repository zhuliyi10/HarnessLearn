# s12 · Cron Scheduler — 定时触发，不需要人推

> *"给 agent 装上闹钟，它就能自己醒来干活。"*

## 本章要解决的问题

到目前为止，agent 都是**被动**的：没人输入，它就闲着。s11 的后台任务也依赖"下一轮调用"来投递通知。

真正的常驻助手需要**主动触发**：agent 给自己安排未来要做的事（巡检、日报、清理缓存），到点自动执行。这就是 cron 调度。

## 核心架构：双路驱动

```
    +---------+   每秒巡检   +-----------+   到期    +------------+
    | 调度线程 | -----------> | jobs.json | -------> | 事件队列    |
    +---------+              +-----------+          +-----+------+
                                                          |
    用户输入 ------------------------------------+         |
        |                                       |         |
        v                                       v         v
    +----------------------------------------------------------+
    |                  主循环 (select 双路)                      |
    |   有用户输入 -> 处理     |    有定时事件 -> agent_loop      |
    +----------------------------------------------------------+
```

关键在主循环用 `select` 同时监听两路：

```python
ready, _, _ = select.select([sys.stdin], [], [], 1.0)  # 最多等 1 秒

if ready:
    query = sys.stdin.readline()    # 用户输入来了
    ...
else:
    # 没输入：处理到期的定时任务
    job = CRON.events.get_nowait()
    trigger = f"[定时触发 {job['id']}] 请执行: {job['prompt']}"
    history.append({"role": "user", "content": trigger})
    agent_loop(history)             # <-- agent 被自己唤醒
```

`select` 的 1 秒超时让主循环每秒醒一次去检查事件队列——这样既不等死用户输入，也不忙轮询。

## 三个设计点

1. **调度表持久化**：任务存 `cron/jobs.json`，重启不丢。agent 的安排跨进程存活。
2. **触发 = 注入一条 user 消息**：`[定时触发]` 前缀让模型知道这不是用户说的话，是闹钟。
3. **最小间隔保护**：`every_seconds` 强制 ≥5，防止 agent 给自己设个 1 秒循环把上下文和钱包都烧穿。

## 试一试

```sh
python s12_cron_scheduler/code.py
```

```
s12 >> 帮我设一个定时任务：每 30 秒把当前时间追加写到 heartbeat.log
```

然后**别输入任何东西，静静等 30 秒**——你会看到 `[cron] ⏰ 触发` 自动出现，agent 自己醒来写日志。再让它 `cron_remove` 停掉。

## 动手练习

1. 把"间隔秒数"扩展成"每天 HH:MM 执行一次"（提示：`next_run` 用日期计算）。
2. 给定时任务加执行历史（最近 N 次的结果），并提供 `cron_history` 工具。
3. 思考：多个定时任务同一秒到期，当前代码会串行执行。如果某个任务很慢，会发生什么？该如何缓解？
