# s09 · Memory — 记住该记的，忘掉该忘的

> *"会话内的容量靠压缩（s08），跨会话的知识靠记忆（s09）。"*

## 本章要解决的问题

进程一退出，`messages[]` 就清空了。用户的偏好、项目约定、踩过的坑，下次会话全部归零。

记忆系统要做两件事：**会话结束时沉淀值得记的，会话开始时带上它们。**

## 三个子系统

```
    会话结束
        |
    1. 筛选 selection     这次对话有值得长期记住的东西吗？
        | 有
    2. 提取 extraction    从对话里提炼出结构化记忆条目
        |
    3. 整理 consolidation 新旧记忆合并：去重、更新、淘汰
        |
    memory/memories.json
        ↓
    下次会话启动时注入 SYSTEM
```

### 1+2. 筛选与提取

为了省一次 API 调用，代码把筛选和提取合并成一次请求：让 LLM 审查对话记录，**没有值得记的就输出 `NONE`，有就输出 JSON 数组**。

提取的 prompt 明确了取舍标准：

```
值得记的: 用户明确表达的偏好/约定、项目的重要事实、踩坑教训。
不值得记的: 一次性任务细节、临时输出、闲聊。
```

还有一条硬要求：**`content` 必须脱离对话上下文也能看懂**——因为记忆会在未来某个完全陌生的会话里被读到。

### 3. 整理

新记忆不能无脑追加，否则记忆库会充满重复和过时信息。整理规则：

1. **重复 → 合并**成一条；
2. **矛盾 → 保新弃旧**；
3. **过时 → 删除**；
4. **总量封顶**（20 条），防止记忆库自己变成新的上下文负担。

整理失败时降级为直接追加——**宁可有冗余，不能丢记忆**。

## 记忆的注入

会话启动时，`MemoryStore.render()` 把记忆库拼进 SYSTEM：

```python
SYSTEM = f"""你是一个位于 {os.getcwd()} 的编程 agent。
{STORE.render()}"""     # "你记得以下关于用户和项目的事实..."
```
