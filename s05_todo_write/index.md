# s05 · TodoWrite — 没有计划的 agent 走哪算哪

> *"先列步骤再动手，完成率翻倍。"*

## 本章要解决的问题

给模型一个 5 步以上的任务，它常常干到一半就偏题、漏步、或者忘了最初的目标。原因是：**目标只存在于上下文里，会被后续的工具输出一点点淹没。**

解法不是写代码替模型规划，而是给它一个**外部工作记忆**——`todo_write` 工具，让它自己管理一份任务清单：

1. **动手前**：把全部步骤列出来（`pending`）；
2. **做每一步前**：把该步标为 `in_progress`（同时只能有一个）；
3. **做完一步**：标为 `completed`，再开始下一步。

每次更新，harness 都把渲染后的完整清单作为 `tool_result` 回传——这相当于不断提醒模型"你在哪、还剩什么"。

## 为什么有效

| 机制 | 作用 |
|---|---|
| 显式列计划 | 强迫模型先想清楚全部步骤，而不是边做边想 |
| 状态回传 | 每步都有"进度提醒"，防止长任务中迷失 |
| 单 in_progress 约束 | 强制串行推进，避免模型同时开几个坑 |
| 人类可见 | 用户随时看到 `[x]/[~]/[ ]` 清单，信任感大增 |

**关键认知**：todo 不是 harness 替模型做的编排，而是给模型的一个自我管理工具。列什么、怎么推进，依然是模型决定的。

## 代码要点

`todo_write` 是**整表替换**语义——每次传入完整列表，直接覆盖旧状态。这样模型不用算增量，简单可靠。

两个校验值得注意：

```python
# 1. 状态合法性
if status not in VALID_STATUS: return "错误: ..."

# 2. 同时只能有一个 in_progress
if len(in_progress) > 1:
    return "错误: 同时只能有一个 in_progress 的 todo，请一次只做一件事"
```

校验失败时返回清晰的错误信息，模型会自己修正再试。

## 试一试

> **安全提示**：代码会执行模型生成的 shell 命令。建议在一个临时测试目录中运行。

```sh
python s05_todo_write/code.py
```

试试这些 prompt：

1. `帮我创建一个 Python 计算器项目：建目录、写 calculator.py（加减乘除）、写 test_calculator.py、跑测试确认通过`
2. `把 calculator.py 里的除法加上除零保护，并补一个除零的测试用例`
3. `现在几点了？`

**观察重点**：绿色的 todo 清单如何从 `[ ]` → `[~]` → `[x]` 逐项推进，且任何时刻只有一个 `[~]`。

- Prompt 1：多步任务。模型会先 `todo_write` 列出完整计划，再逐项推进——todo 列表就是它的"外部工作记忆"，每次更新都会回传进 messages。
- Prompt 2：中途追加需求。观察模型是把新步骤并进现有列表，还是整表重写（`todo_write` 是整表替换）。
- Prompt 3：简单的一步任务。SYSTEM 里写明"简单的一步任务不需要 todo"——观察模型是否真的跳过了规划，直接回答。

## 动手练习

1. 给 todo 增加 `blocked` 状态，并在渲染时展示。想想什么场景下模型会用到它。
2. 把 `todo_write` 的整表替换改成"按 id 增量更新"，体会两种语义对模型使用方式的影响。
3. 观察：模型会不会在"一步就能做完"的小任务上也硬列 todo？如何调整 SYSTEM prompt 来约束？
