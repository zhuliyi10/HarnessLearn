# s17 · Goal Loop — 目标决定循环什么时候真正结束

> *"执行者只管干活，是否完成由独立的眼睛判断。"*

## 本章要解决的问题

s01 的循环在"模型不再调用工具"时结束。但**停止 ≠ 达成**：

- 模型可能中途放弃，"剩下的部分你可以自己完成"；
- 模型可能自我感觉良好地宣布完成，实际测试根本没跑；
- 模型遇到一个错误就摊手，其实换个思路就能解决。

对"给一个目标，必须达成"的场景（自动化交付、无人值守任务），需要一个**目标闸门**：每次执行者想收工时，由独立判断器审查，没达成就自动续跑。

## 三态裁决

```
    执行 agent 跑一轮（想收工了）
        |
        v
    独立判断器（另一次 LLM 调用）审查证据
        |
    +---+------------------+------------------+
    | done                 | continue          | give_up
    v                      v                   v
    真正结束               审查意见注入为        目标不可能 / 反复失败
    输出最终答案           user 消息，           / 超过续轮上限
                          自动续跑下一轮        → 控制权交还用户
```

| 裁决 | 含义 | 动作 |
|---|---|---|
| `done` | 有证据表明目标达成 | 闭环成功，输出结果 |
| `continue` | 未达成但还能推进 | 审查意见变成下一条 user 消息，续轮 |
| `give_up` | 目标不可能或已到上限 | 停下，把情况如实交还用户 |

## 三个关键设计

### 1. 审查器必须独立

审查用的是**另一次 LLM 调用、另一套 SYSTEM**（`REVIEWER_SYSTEM`），它不看执行者的内心戏，只看工作记录里的证据。执行者和审查者分离，避免"自己给自己打分"的偏袒。

### 2. 续轮 = 注入一条 user 消息

`continue` 时不需要任何特殊机制——审查意见就是一条普通的 user 消息：

```python
messages.append({"role": "user", "content":
                 f"[审查意见] 目标尚未达成。{feedback}\n请继续。"})
```

对执行 agent 来说，这只是"用户又催了一句，还告诉了方向"。这就是 harness 的优雅：**新行为由消息驱动，不改循环结构。**

### 3. 永远有上限

`MAX_CONTINUATIONS = 3`。审查-续轮机制一旦失控就是无限烧钱循环，上限是底线。超限或 `give_up` 时**把控制权交还用户**，并附上最后一次审查意见——失败也要失败得明白。

## 双向约束

注意 SYSTEM 里对执行者的要求：

```
完成任务后必须用工具验证结果（跑测试、检查文件），不要凭感觉宣布完成。
```

闸门不仅在外层把关，也通过 prompt 引导执行者**自证**。内外两层配合，"假完成"的空间被压到最小。

## 试一试

> **安全提示**：代码会执行模型生成的 shell 命令。建议在一个临时测试目录中运行。

```sh
python s17_goal_loop/code.py
```

试试这些目标（给**可验证**的目标效果最好）：

1. `创建 prime.py 实现判断素数的函数，并创建测试文件运行确认全部通过`
2. `写一个故意失败的测试 test_fail.py，然后让所有测试通过`
3. `把 2+2 算成 5 并写个测试证明它`

**观察重点**：执行 → `⚖ 审查中...` → 审查器给出 `continue` / `done` / `give_up`——完成标准由独立的审查循环判定，不由执行者自己说了算。

- 目标 1：如果测试没跑或没过，审查器给出 `continue` 并续轮，直到 `✅ 目标达成`——执行者想"糊弄"过关也没用。
- 目标 2：目标本身自相矛盾。观察审查器和执行者如何拉扯，以及最终是反复重试还是放弃。
- 目标 3：不可能完成的目标，观察 `give_up` 路径——好的 goal loop 要知道何时止损，而不是无限烧 token。

## 动手练习

1. 给审查器加"证据要求"：done 时必须引用记录中的具体工具输出作为证据。
2. 把 `MAX_CONTINUATIONS` 耗尽后的现场（messages 摘要）存盘，方便事后人工复盘。
3. 思考：审查器本身也是 LLM，它可能误判（把没完成的判成 done）。还能加什么机制进一步兜底？（提示：确定性验证——目标里要求"测试通过"时，直接跑测试命令看退出码，不依赖 LLM 判断）
